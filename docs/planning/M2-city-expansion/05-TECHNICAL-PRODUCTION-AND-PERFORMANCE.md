## Part 1 — Production strategy (§H)

### 1.1 Modular prefab approach

One `.rbxmx` per zone, generated by a **new** generator
(`tools/gen_city_prefabs.py`, authored in M2-A, not in this PR), following the
existing `tools/gen_world_prefabs.py` conventions:

| Prefab | Parts (target) | Pivot | Owner |
|---|---|---|---|
| `HouseExterior.rbxmx` | 90 | `(0, 0, 0)` | M2-A |
| `StreetBlock.rbxmx` | 80 | `(0, 0, 40)` | M2-A |
| `TownCenter.rbxmx` | 220 | `(0, 0, 112)` | M2-A shell / M2-B props |
| `CityBoards.rbxmx` | 40 | `(0, 0, 70)` | M2-A |
| `CityGate.rbxmx` | 30 | `(0, 0, 168)` | M2-A |
| `CityBackdrop.rbxmx` | 8 | `(0, 0, -160)` | M2-A |
| `CityProps.rbxmx` | 60 | shared kit | M2-A |
| `ShopRowElectronics.rbxmx` | 120 | `(70, 0, 84)` | M2-B |
| `ShopFurniture.rbxmx` | 100 | `(-70, 0, 84)` | M2-B |
| `EventPlaza.rbxmx` | 160 | `(-112, 0, 134)` | M2-B |
| `EventPlaza_PopUp.rbxmx` | 60 | `(-112, 0, 134)` | M2-C |
| `ShopCosmetics.rbxmx` | 90 | `(70, 0, 108)` | M2-C |
| `ShopUtility.rbxmx` | 50 | `(70, 0, 132)` | M2-B |

Rules:

- **Pivot = zone origin** from the coordinate contract. Placement is
  `CFrame.new(zoneOrigin)`, never hand-nudged.
- **No cross-prefab references.** A shop never parents into another prefab.
- **Kit of parts.** Benches, lamps, bins, awnings, signs, fences, planters are
  authored once in `CityProps` and repeated by reference in the generator.
- **No `Script`/`LocalScript`/`ModuleScript` descendants** in any exported
  prefab (same acceptance gate as `Bedroom.rbxmx`).
- **No unique meshes.** `BasePart` primitives + built-in materials only.

### 1.2 Streaming-friendly layout

```text
Workspace
├── BuzzerRoom_<UserId>   ModelStreamingMode = Atomic
└── City                  Folder
    ├── City_Zone_*       ModelStreamingMode = Atomic
    └── City_Backdrop     ModelStreamingMode = Persistent
```

- **Atomic** zones: a zone appears/disappears whole, never as floating awnings.
- **Persistent** backdrop: 8 parts, always loaded, keeps the window vista.
- **Compact bounding box** (224 × 198 walkable) means the whole town center is
  usually within the streaming target radius anyway; streaming is insurance,
  not the primary performance lever.
- **Door transition:** if the destination zone is not streamed in yet, the
  client calls `Workspace:RequestStreamAroundAsync` for the exterior threshold
  **before** the fade completes. The fade is 0.25–0.35 s — enough for a local
  catch-up in the same place.
- **No seamless exterior/interior culling tricks.** The room is a real clone;
  the shell wraps it. Do not hide the room while outdoors (the window would
  show the void).

### 1.3 Low-poly, Roblox-native art strategy

- Reuse the existing 16-color world palette
  (`docs/design/02-COLOR-AND-MATERIALS.md`). No new color tokens:
  - asphalt → `ink` / `navy`
  - concrete → `plaster`
  - awnings → `sage` / `sage_dark`
  - signage → `amber` / `cream`
  - metal → `metal`
- Materials: `SmoothPlastic`, `Wood`, `Metal`, `Fabric`, `Concrete` only.
  No `Neon` geometry except ≤ 0.1-stud indicator strips and blinking antenna
  tips.
- **Silhouette-first:** each shop must be identifiable as a 6-part massing
  blockout before detail is added.
- **Detail budget:** ≤ 25% of a zone's parts may be non-structural decoration.
- **Text:** `SurfaceGui` with authored strings, max one per sign. No 3D text
  instances, no uploaded images.

### 1.4 Anchor & marker philosophy

Anchors are **data contracts**, not decorations.

1. Every interactive location has exactly one named anchor.
2. Anchors are invisible, anchored, non-colliding, non-touchable, non-queryable.
3. Names are prefixed (`City_`) and frozen once a prefab is merged.
4. Nothing saves a reference to an anchor; the server re-resolves by name.
5. Missing anchor = loud, recoverable failure (same pattern as
   `WorldService.Spawn`), never a silent half-built city.
6. Anchors live in `City_Anchors` (a Folder), not inside decorative models.
7. Prompts are server-created and parented to the anchor, exactly like
   `DashboardPromptAnchor` → `DashboardPrompt`.

### 1.5 Minimizing expensive redesigns

Lock these **before** any art is commissioned (G1):

| Freeze | Value | Why |
|---|---|---|
| Grade | `Y = 0`, flat | avoids ramps/stairs/camera work |
| Grid | 8 / 16 studs | every future lot snaps |
| Facade depth | 24 studs | shops stay interchangeable |
| Lot width | 24 studs | districts reuse the same kit |
| Zone extents | table in `02` | prevents drift and re-layout |
| Anchor names | table in `02` | prevents service rewrites |
| Streaming roots | `Workspace.City` | prevents re-parenting churn |
| Shop interaction model | prompt → existing UI | prevents a second economy |
| No closed interiors | open-front kiosks | prevents camera/lighting rework |

If one of these must change later, it is a **contract change**, not a polish
task: update this blueprint, the anchor table, and the blockout together.

### 1.6 MVP city vs future city

- **MVP city (M2-A + M2-B):** one street, one town center, three shops, one
  plaza, one gate, six signposts. Roughly 960 parts. One player. No schema
  change.
- **Future city (M2-C+):** one additional district, transit, cosmetics shop,
  event variety, rooftop venue. Needs `cityUnlocks` flags and director
  approval.

The MVP is deliberately the **smallest city that can host the loop**, not the
first slice of a bigger city.

## Part 2 — Scope control (§I)

### M2-A — Exterior Foundation

| Field | Definition |
|---|---|
| **Exact scope** | House shell, stoop, street, town-center shell (paving, fountain, lamps), boards kiosk, future-gate visual, north backdrop, door prompts, city unlock gate, static `CityService` clone |
| **Must-have** | Frozen coordinate contract; door in/out prompts; `cityUnlocked` derived from existing fields; board prompt opens the existing mission surface; streaming verified; no new economy; no schema change |
| **Deferred** | Shop interiors, cosmetics, event plaza dressing, minimap, zone labels, bus stop interaction, NPC crowd |
| **Art scope** | 6 prefabs + shared props kit; ~520 BaseParts; blockout → detail pass; no signage polish beyond one sign per zone |
| **Risk** | **Medium** — door threshold alignment and roof/camera clipping are the two ways this fails |
| **Exit gate** | Studio play on phone + desktop: walk out, see the hub, open the board, walk back; 30 FPS baseline; no streaming pop at the door; director visual sign-off |

### M2-B — Functional City Hub

| Field | Definition |
|---|---|
| **Exact scope** | ElectroMart (opens existing Upgrades), Warung Serba Ada (free utility panel), Rumah Rapi (cosmetic-only panel + decor placement), event plaza permanent shell, daily brief board (F1), landmark stamps (F4), zone labels, return-home HUD chip |
| **Must-have** | All shop purchases server-confirmed through existing paths; cosmetic items provably stat-free; daily brief reuses an existing reward; stamps cosmetic-only; no new economy constants |
| **Deferred** | Cosmetics shop (S3), pop-up events (F2), themed weeks (F3), seasonal overlay (F5), transit, districts, minimap |
| **Art scope** | 4 shop/venue prefabs + ~10 cosmetic room items; ~430 additional BaseParts; signage + awning polish |
| **Risk** | **High** — cosmetic catalog and any new persisted field expand scope; the shop UI is the first new client surface since M1 |
| **Exit gate** | Full loop observed on a real phone: publish → leave → board → shop → return → publish; cosmetic item appears in the room after rejoin; no double charge; no navigation dead end |

### M2-C — Expanded Districts

| Field | Definition |
|---|---|
| **Exact scope** | Cosmetics shop (S3), event repertoire (F2/F3/F5), bus-stop fast travel, rooftop venue hook, **schema v2 `cityUnlocks`**, one new district gate opening (Office District stub) |
| **Must-have** | Backward-compatible profile reader; rollback plan; director-approved district content; no new economy tier |
| **Deferred** | Agency Tower interior, Influencer District, full Office District content, multiplayer, monetization |
| **Art scope** | 1 new district shell + event dressing variants; ~400 additional BaseParts; highest art cost |
| **Risk** | **High** — schema migration is the single most dangerous change in the whole program |
| **Exit gate** | Dev-universe migration + rollback rehearsal; old profiles load unchanged; district unlock cannot be forged; performance re-profiled |

### Phase dependency graph

```text
M1 complete (BS-14 Go)
        │
        ▼
M2-A  ──►  M2-B  ──►  M2-C
(foundation) (hub)     (districts)
   │           │           │
   │           │           └─ needs schema v2 + director
   │           └─ needs cosmetic catalog approval
   └─ needs coordinate + anchor freeze (G1)
```

**No phase may start before the previous phase's exit gate.** M2-B art can be
blocked out in parallel, but not merged.

## Part 3 — Performance & Roblox constraints (§K)

### 3.1 Streaming assumptions

| Setting | Recommendation | Note |
|---|---|---|
| `StreamingEnabled` | `true` | verify on the live place at implementation time |
| `StreamingTargetRadius` | 256 | compact city; whole hub stays loaded |
| `StreamingMinRadius` | 64 | player's immediate surroundings always solid |
| Zone `ModelStreamingMode` | `Atomic` | no partial shops |
| Backdrop `ModelStreamingMode` | `Persistent` | 8 parts, always visible from the window |
| Player room | `Atomic` | never half-built |

Do not rely on streaming alone to hit frame time. Measure.

### 3.2 Part budget mindset

| Scope | Test budget | Hard cap |
|---|---|---|
| Bedroom (existing, measured in `Bedroom.rbxmx`) | 155 | 350 |
| Street + home shell + backdrop | 178 | 250 |
| Town center | 220 | 300 |
| Each shop | 50–120 | 150 |
| Event plaza | 160 | 220 |
| Whole city, M2-B | ~958 | 1,200 |
| Whole city, M2-C | ~1,500 | 1,800 |

Budgets are **authoring tests**, not engine limits. If a zone exceeds its cap,
cut props, not structure.

### 3.3 Density recommendations

- Walkable clear width ≥ 6 studs on all paths; ≥ 8 studs around the fountain.
- Max 1 decorative prop per 4×4 stud footprint in walkable areas.
- Sign clutter: max 3 readable signs in one camera frame.
- Building height 12–16 studs; nothing walkable taller than 20.
- Vertical stacking is forbidden in MVP (no balconies, no stairs) except the
  rooftop venue hook (deferred).

### 3.4 NPC population strategy

| Rule | Value |
|---|---|
| Max ambient NPCs | 6 total, ≤ 2 visible per zone |
| Ownership | client-local clones (server spawns nothing) |
| Movement | 2–4 authored waypoints, `Humanoid:MoveTo`, no pathfinding |
| Collision | non-colliding, `CanQuery = false` |
| Animation | reuse existing trainee rig animation set; no new animation asset |
| Economy | **zero** interaction with income, workers, or persistence |
| Vendors | static parts/props, not rigs |
| Despawn | NPCs outside the streaming radius simply do not exist |

### 3.5 Lighting & audio

- Total city `PointLight`s ≤ 8; only 2 with `Shadows = true`.
- No `SurfaceLight` spam; no `SpotLight` in MVP.
- No bloom/atmosphere stack; one `Atmosphere` with low density if needed.
- Audio: ≤ 2 ambient loops, rights-reviewed, volume/mute respected, never
  blocks gameplay on load. Silence is acceptable.

### 3.6 Mobile-first checklist

- [ ] 360×640 portrait and 640×360 landscape walkthrough
- [ ] All prompts reachable without camera clipping into a wall
- [ ] No shop requires entering a closed interior
- [ ] Text ≥ 14 reference pixels; 44×44 touch targets for any new button
- [ ] No UI element under the notch/safe area
- [ ] ≥ 30 FPS on baseline mobile, no persistent > 100 ms script stalls
- [ ] First city load (walk out) has no visible pop-in
- [ ] Returning home restores controls and camera exactly once

### 3.7 Script/network constraints

- No per-frame scans of the city tree.
- No `RunService.Heartbeat` loop over city parts.
- Prompts validated server-side by anchor name + distance (reuse 10/12-stud
  constants), never trusted from the client.
- No new remote for city purchasing; reuse existing state/snapshot flow.
- Cosmetic panels, if added, follow the existing request/reply discipline
  (idempotent IDs, no optimistic grant).
- All city content is read-only static geometry except prompt state.

### 3.8 Failure behavior

| Failure | Required behavior |
|---|---|
| Missing city prefab | Surface an error; player stays in the bedroom; no empty world |
| Missing anchor | Do not create the prompt; log the anchor name; keep the zone walkable |
| Zone not streamed at door | Request stream, hold the fade, then place the character |
| Cosmetic purchase unconfirmed | Do not show the item; reconcile from saved ownership on rejoin |
| Save blocked | Disable city purchases and board claims; HUD shows the blocked state |
| Player dies outside | Respawn indoors at the frozen `Spawn` (existing behavior) |

## Part 4 — Testing obligations (for the implementation milestone)

This branch authors **no tests**. The M2-A implementation must add:

| Test | Assertion |
|---|---|
| `CityService.spec` | static city clones once; required anchors exist; no scripts inside |
| Door prompt spec | prompt identity + 12-stud validation; no prompt on the frozen `Door` part |
| Unlock spec | `cityUnlocked` is false until tier 2 + 2 desks + 2 workers |
| Anchor spec | all `City_*` anchors exist exactly once, correct class, invisible |
| Shop routing spec | ElectroMart opens the existing Upgrades surface; no new price table |
| Cosmetic spec | cosmetic ownership cannot change yield/reveal/worker rate |
| Streaming spec | zone models are `Atomic`; backdrop is `Persistent` |
| Performance evidence | phone + desktop capture, FPS and part counts recorded |

Existing tests must remain untouched and green.
