# Buzzer Simulator — Testing and Quality

## Evidence ladder and scope honesty
A Rojo build proves place assembly, not gameplay. Luau specs prove rules, not real network/saves. Studio Play proves connected behavior; a published isolated **dev-universe** rejoin probes DataStore; emulator and a real lower-end phone probe usability/performance. V0 is an **internal technical prototype**; no V0 gate alone authorizes public launch. No gameplay code, Studio test, device test or asset quality check was executed while revising this plan.

| Gate | When | Required proof |
|---|---|---|
| G0 static/rules | each task | Production/test Rojo builds; discovered specs with nonzero assertions and zero failures; optional pinned lint/typecheck |
| G1 connected slice | V0A | Recorded `OldCRT` prompt + productive phone/organic/mission/phone journey in Studio: publish inside CRT BuzzerOS; payout matches equipped phone, not CRT; exact server Cuan and world swap |
| G2 data safety | V0B | Dev-universe rejoin matrix, forced fake-store failure/lease races, post/claim/purchase idempotency, no blank overwrite |
| G3 internal UX/art | V0C | Phone/PC/tablet emulator, dashboard-only `OldCRT.rbxmx` and cheap/fast productive phone variants displayed one at a time, camera/close/expiry, uncoached first-run observation; **not** beta/public approval |
| G4 M1 incremental | BS-11–13 | Context/tier/catalog validator, PC income/model, two desk/hire stages, three-style simulator and live session probes |
| G5 closed-beta candidate | BS-14 | Same exact build reruns G0–G4, real phone, 20m idle, content originality, security/perf/write-pressure, rollback, director beta Go/No-Go; **not** wider release |

## Deterministic test matrix
- **Pure rules/catalog:** `postImpact(100,strong,1)=120`, weak starter75, weak PC94<100, two weak starter posts>=100; organic strong/weak cheap15/9, fast24/14, PC37/22; 18/16/13s reveals; tier1 300/3, tier2 1600/3 and shipped-tier clamp. Reject NaN/infinity/negative amounts. Every shipped mission has three templates and (M1) three contexts; every organic context has three. Private `score=2*trendMatch+audienceMatch` has one unique winner for every mission/context and organic context; exercise intentional tie/rejected fixture, and each mission's three contexts select different winners.
- **Mission/organic:** First `organic_snack` after fresh join, then sequence advances only on confirmed publish; no reroll by UI reopen; first food `meal_time`, subsequent context rotates per saved mission counter. Accept invalid/locked/duplicate; publish unknown/wrong template/run, while either mode pending, or third campaign post. Strong food post credits organic15 at settlement, then bonus80 exactly once at claim; weak post credits9 and needs two; organic-only post credits15 without a mission and never advances an accepted mission. Test settlement at `settleAt-1`, `settleAt`, `settleAt+1`, duplicate settlement, close/rejoin while pending and after payout. Preserve older saved context IDs if catalog grows.
- **Economy:** Guided organic15 + food post15 + claim80 =110; fast phone50 leaves60 and increases strong payout15->24. Post from BuzzerOS at `OldCRT` with cheap then fast phone: only `profile.deviceId` changes payout/reveal, never terminal art; after PC purchase, phone prop is inert and only PC yield applies. PC220 from exact-next fast; PC strong37/weak22, no device yield stacking. Desk1 180+worker1 500 gate on PC/tier1/free slot; desk2 250+worker2 750 gate on tier2/first worker/free slot; buying at exactly price succeeds, one less fails. 30 healthy seconds banks45 with one worker,90 with two; fractional 1-second ticks carry; a simulated 75-second connected stall processes bounded <=60-second chunks **without losing the remaining 15 seconds**, and no disconnect interval counts. Confirmed balance excludes unbanked preview; no offline Cuan; purchases first durably bank pending worker credit before spending. Failure freezes actions and does not leak preview as spendable. Compare the passive-focused ten-minute-after-first-hire row: **870 banked**, not 900, because the final 20 connected seconds remain unbanked at that observation point.
- **Persistence:** Fresh v1 key, lease token conflict/expiry, 90s renewal, 30s bank/240s lease, queued saves, ambiguous write with identical operation ID, saved `recentMutationOutcomes` replay after rejoin, lost/late settlement save, failed read never seeds blank, future/corrupt schema preserved, quit/BindToClose overlap. Recover organic/mission pending, organic paid, mission ready/claimed, fast/PC, both desks and workers. A confirmed payout or purchase survives rejoin; unbanked worker preview may lose <=one checkpoint window on crash. Fake adapter covers uncertain write response; real dev-store separately verifies API behavior.[2][3]
- **Network/security:** Unknown action, extra key, oversize strings/tables, NaN/infinite value, forged price/impact/Cuan/fit/trend/context/time/rate/device, other user ID, repeated `requestId` and `runId`, rapid publish and cross-mode double publish, out-of-range/wrong-room prompt, command before load, after death or lease loss. Server derives `Player` from event and validates exact server prompt, distance and session independently of client UI.[4] After valid `DashboardPromptAnchor`, server sends `Snapshot:FireClient(player,{kind="OpenComputer",dashboardSessionId=...,expiresAt=...,serverTime=...,state=...})` only to that player; denied prompt uses `OpenComputerDenied` without session/camera transition; `State` cannot open UI. No fourth remote or client OpenComputer action. Old-session Buy/Close after reopen cannot execute/close current session.
- **Protocol/reconciliation (fake-clock/router/reducer):** Mutation ID `mut-0001` times out; query ID `qry-0002` is distinct, `GetSnapshot.payload.lookupRequestId="mut-0001"`, Reply correlates `qry-0002` and lookup correlates `mut-0001`. Test APPLIED persisted result, live REJECTED, PENDING write, UNKNOWN/evicted outcome; later Reply/State delivered out of order respects greatest revision and never duplicates credit. Repeating the identical mutation with `mut-0001` while PENDING in the same live session joins the reserved in-flight mutation or replays its result without a second write/credit; same ID with a different intent is INVALID_INPUT. UNKNOWN in **any** session means no automatic retransmit/new-ID mutation. When a fake-store write is held, query returns PENDING with the last **confirmed** snapshot promptly, not an uncommitted balance; lookup does not itself create a post. Query without lookup returns no lookup; query does not extend idle deadline, but due-post settlement triggered during query is counted only once under its own stable operation ID.
- **Dashboard expiry (fake-clock/client lifecycle):** At 599s idle UI remains open, at >=600s server sends once `ComputerSessionExpired` and rejects new session-bound actions with `SESSION_EXPIRED`; repeated `GetSnapshot`/worker ticks cannot keep it alive. A mutation admitted at 599s refreshes the deadline (reported in matching `Reply.dashboardSession`); alternatively force expiry while the admitted mutation is saving, and its late Reply updates HUD only without reopening. A valid action's updated deadline prevents a false local expiry, while repeated GetSnapshot never refreshes the server deadline. Close while opening, a second valid prompt while already open, death during camera tween, missed-expiry local watchdog and duplicate expiry restore original camera/subject/movement/focus **once**; the second prompt must not overwrite the pre-open restore state, and stale previous-session expiry/Close cannot close a fresh session. Reopening requires prompt; no stale pending mutation is reissued.
- **Write-pressure (reproducible fake-store + isolated dev universe):** Count one save per accept/publish/settle/claim/purchase/hire; zero per prompt/close/ordinary snapshot/lookup/rejection (except an already-due post settled by query). Run 25s organic PC loop (4.8 writes/min), 65s strong-mission loop (3.69/min), 90s alternating loop (4/min), reveal-only 13s stress (9.23 organic or 18.46 mission/min), plus 0/1/2 online workers and three rapid purchases. Fake single-key adapter imposes 0ms then 6s service delay, transient throttle and ambiguous success; assert bounded queue/backpressure, stable IDs, no speculative confirmed Cuan, no duplicate saves on bank/lease coincidence, idle worker bank by 30s healthy connected time, lease by 90s, and eventual reconciliation or explicit block. Record in dev universe attempted/confirmed writes/min, read/write budget, p50/p95 save latency, throttles/retries, profile bytes and time-to-visible-confirmation; do not assert a platform-per-key latency from the fake delay.[1][3]

## Device, performance and playtest gates
Studio emulator: 360×640 portrait, 640×360 landscape, 768×1024 tablet, 1280×720 and 1920×1080 desktop; one real lower-end Android phone. If unavailable, mark real-device G5 **blocked**, not passed. Check safe areas, bottom Create/Claim/Buy reachability, >=44×44 reference targets, readable text, keyboard/gamepad/touch focus, Escape/Close, resize while open, reduced motion, text fit explanation, and distinct banked versus unbanked Cuan.[6][11]

**Initial targets, not Roblox limits:** Smooth >=30 FPS on chosen lower-end phone; no persistent >100ms tab-change/settlement freeze; <=250 decorative BaseParts in initial room until measured; max 12 authored + 10 own feed cards, 2 local worker rigs, 1 aggregate server scheduler. Profile 20 connected idle minutes with both workers, repeated open/close for listener leaks, and reconnect after idle for profile recovery. Record model/quality setting, frame-time distribution, memory, script time, replication and draw cost. Cut measured bottlenecks instead of assuming a part-count number proves performance.[9]

Run a small uncoached sample and report sample size, device, prior simulator familiarity, exact build and distribution. Observe: CRT prompt discovery and dashboard-only versus productive-phone comprehension; first organic payout; understanding organic versus claim bonus; different template winners under successive contexts; recognition of phone/PC/worker visual changes; time to PC/first/second hire; voluntary use of organic versus missions; second-session return; whether 18s reveal leaves dead time. Modeled first-hire **7:25 active / 9:31 balanced / 10:50 passive-focused** and second-hire **11:45 / 14:01 / 22:20** are hypotheses under fixed durations, not pass/fail player guarantees. If context choices are unclear, rewrite copy before adding modifiers. If idle outpaces active too early, change rates/costs and rerun all policies; do not punish the player with an arbitrary Cuan cap.

## Closed-beta Go/No-Go; wider release remains separate
**Closed-beta Go** only when exact candidate has green builds/tests, Studio two-mode journey, dev-universe saved-state/rejoin, replay/forgery denial, reviewed fictional copy/assets, human visual sign-off, lower-end phone evidence, measured idle/balance and write pressure, and rehearsed rollback with compatible schema reader. **No-Go:** double grant, confirmed credit lost, blank-overwrite, client-forged payout, remote prompt anywhere, PC purchased but unrecoverable world, worker credit while offline, unbanked preview spendable, only one authored template optimal in all contexts, broken mobile Close/Create/Claim, session-expired camera lock, uncontrolled single-key write queue, or undocumented schema incompatibility. Performance target failures require measured optimization or an explicit director decision; never a silent pass. Keep production DataStore out of Studio API tests.[1][3] Wider release needs observed beta retention/comprehension/balance and a separate director review; do not graft M2 features onto M1 to mask missing evidence.
